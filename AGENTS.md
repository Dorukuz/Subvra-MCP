# Subvra — Agent Instructions

## Overview

Subvra is an App Store screenshot generation SaaS built with Next.js 15 (App Router), TypeScript, Tailwind CSS v4, MongoDB, Redis/BullMQ, Firebase Auth, Stripe, and OpenAI GPT Image 2. See `docs/PROJECT_PLAN.md` for the full architectural spec.

## Cursor Cloud specific instructions

### Quick reference

| Task | Command |
|------|---------|
| Dev server | `npm run dev` (Turbopack-enabled) |
| Lint | `npm run lint` |
| Type check | `npm run type-check` |
| Build | `npm run build` |
| Start prod | `npm run start` |
| DB setup (indexes) | `npm run db:setup` |

### Project structure

- `app/` — Next.js App Router pages and API routes
  - `app/(marketing)/` — landing, SEO, legal pages
  - `app/(auth)/` — sign-in/up flows
  - `app/(dashboard)/` — generator, history, billing, team
  - `app/api/` — webhooks, generation, uploads, health check
- `lib/` — shared modules (mongodb, redis, apple-presets, etc.)
- `jobs/` — BullMQ processor workers
- `public/templates/` — device frame templates and overlays
- `docs/` — project planning documents

### Environment variables

Copy `.env.example` to `.env.local` for local development. At minimum, `MONGODB_URI` and `REDIS_URL` are needed for full functionality. External service keys (Firebase, Stripe, OpenAI) are required for their respective features but the app starts without them.

### Dev server

`npm run dev` runs Next.js with Turbopack on port 3000. The health check endpoint at `/api/health` is available without any external services.

### API routes

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/health` | GET | Health check (no auth needed) |
| `/api/auth/session` | POST | Firebase token → user upsert + trial credits |
| `/api/generate` | POST | Screenshot generation (queues BullMQ job) |
| `/api/drafts` | POST | Save anonymous draft before auth |
| `/api/billing/checkout` | POST | Create Stripe Checkout session |
| `/api/billing/portal` | POST | Create Stripe Customer Portal session |
| `/api/webhooks/stripe` | POST | Stripe webhook receiver |
| `/api/admin/stats` | GET | Admin analytics aggregation |
| `/api/admin/export` | GET | Admin CSV export |

### Key lib modules

- `lib/auth.ts` — `verifyAuth()`, `requireAuth()`, `requireAdmin()`, `upsertUser()`
- `lib/credits.ts` — `debitCredits()`, `creditWallet()`, `grantTrialCredits()`, `getWalletBalance()`
- `lib/stripe.ts` — Stripe client + plan/topup price config
- `lib/openai.ts` — OpenAI client + `generateImage()` wrapper
- `lib/image-pipeline.ts` — Sharp processing for Apple device resolutions
- `lib/rate-limit.ts` — Redis-based rate limiter
- `lib/email.ts` — Resend transactional email
- `lib/db/models.ts` — TypeScript interfaces for all MongoDB collections
- `lib/db/indexes.ts` — Index setup function

### MongoDB (self-hosted on same VPS)

MongoDB runs on the same VPS in production (not a managed service). For local dev:
- Start MongoDB: `mongod --dbpath /data/db --bind_ip 127.0.0.1`
- Default URI: `mongodb://localhost:27017/subvra` (no auth for dev)
- Docker Compose URI: `mongodb://subvra:<password>@localhost:27017/subvra?authSource=admin`
- Create indexes: `npm run db:setup`
- Collections: `users`, `organizations`, `memberships`, `wallets`, `credit_transactions`, `drafts`, `generation_jobs`, `stripe_events`

### Gotchas

- The `lib/mongodb.ts` and `lib/redis.ts` modules use global singletons to survive HMR in development. They do not attempt connection until first use, so the dev server starts even without MongoDB/Redis running.
- Tailwind CSS v4 is used with `@tailwindcss/postcss` — config is in `postcss.config.mjs` and CSS tokens in `app/globals.css` using `@theme inline` with OKLCH color space.
- The `.gitignore` excludes `next-env.d.ts` — it is auto-generated by Next.js on each build/dev start.
- Firebase auth is lazily initialized on the client side to avoid errors when `NEXT_PUBLIC_FIREBASE_*` vars are not set.
- The BullMQ worker (`jobs/generation-worker.ts`) is a standalone process — run separately from the Next.js server. It requires Redis to be available.
- Docker Compose includes `dev` and `production` profiles. Use `docker compose --profile dev up` for development (includes mongo-express on :8081).
- Rate limiter (`lib/rate-limit.ts`) fails-open when Redis is unavailable — requests are allowed but not rate-limited. In production, ensure Redis is always running.
- All API routes except `/api/health` and `/api/drafts` require Firebase auth. The Stripe webhook requires signature verification. Admin routes require `role: "admin"` on the user document.
